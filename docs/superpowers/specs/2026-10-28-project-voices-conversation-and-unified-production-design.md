# Project voices, multi-speaker storytelling and one Production workspace

**Status:** local SQLite-backed, revision-checked **project voice favorites, immutable character-revision voice bindings and source-pinned scene-cast assignments** have separate bounded registries (`0019`–`0021`) (2026-10-28). The embedded Director persists single-scene speaker choices into the source-linked plan and Rust scene-cast registry, resolves browser/server conflicts visibly, and blocks auto-start when cast sync fails. The newly supported preproduction/renderer schema accepts **two to sixteen ordered speech turns within one visual scene**, with stable speaker identity, per-turn voice, separate SHA-addressed speech cache/Jobs attempts, genuine silent pauses and FFmpeg speaker-labeled SRT. The embedded editor adds/removes/edits turns; **Conversation + narration** is available as a one-click synthetic demo and per-scene starting template. The default Pip and Quill voice ID is the same Fish voice until separately edited, not proof of two distinct voices. **Pip and Quill now have distinct bundled vector puppets in landscape/portrait video export, plus verified same-origin importable ZIPs and one-click project-scoped Character Studio starters**; blink, gestures and approximate mouth motion use the measured speech-turn clock in export. Existing custom/revisioned characters are not silently overwritten. **Still missing:** deliberate simultaneous speech overlaps, **mapping a selected Studio/custom revision to actual video-render assets**, Rust multi-browser sync for dialogue/nonvoice scene edits, individually verified cast-voice release rights, real narrated MP4 browser playback and responsive/keyboard QA. **Tracking:** [PR #134](https://github.com/YukiUmetsu/ai-content-generation/pull/134), under [remaining one-click video requirements](../../22-one-click-video-production.md#per-scene-review-evidence-and-remaining-verification). This specification extends [audio ownership](../../13-audio-production.md), [Character Studio](2026-10-26-character-studio-production-design.md) and [Production](../../production-workflow.md); its illustrative multi-speaker JSON includes future behaviors (such as deliberate overlap) that are not supported yet.

## 1. Project voice library and defaults — P0

**Implemented slice:** In Preview & Export → Narration, the compact project-favorites control saves, edits, deletes, reorders and chooses Fish/local voice mappings in a versioned **SQLite project registry**, with browser localStorage retained as a guarded migration/cache copy. `GET /api/project-voices/{project_id}` distinguishes an absent record from an empty list, while `PUT` verifies a monotonic revision with an atomic SQLite compare-and-write. A mismatch between existing browser and server libraries requires an explicit choice; stale writes and offline storage fail visibly. The requested Fish ID is seeded without invented gender/language claims; the active narrator uses the primary when no previous choice exists, and changing a favorite never silently transmits speech. Existing global preferences are claimed by only one project on migration. **Not yet delivered:** server-side project deletion cleanup, server-backed character voice profiles/rights, broader production narrator profile reconciliation across independently configured browsers, project-to-character reuse and true speaker-aware synthesis.

- A project has a **Voices** section inside **Production → Create Video** with a compact searchable list of saved favorite voices. **Save voice** accepts a Fish Audio voice ID (later providers use their own adapter), optional display name, a brief audition/description, and editable tags. At minimum the tag dimensions are **gender** (e.g. female/male/nonbinary/unspecified; descriptive, not inferred from the voice ID), **situation** (narration, conversation, character, tutorial, etc.) and **language** (BCP-47 locale such as `en` or `en-US`). Freeform tags may supplement these but must not masquerade as verified provider metadata. A voice can have multiple situations/languages only when actually supported or explicitly marked user-reported.
- Persist project-scoped, versioned favorite records, with provider, opaque voice ID, nonsecret display metadata, creator-supplied tags, ordered rank, revision, rights/consent reference and dates. **Do not store API credentials, samples, or unapproved provider data** in project JSON, URLs or Jobs. A project may rename/reorder/remove favorites without deleting a previously exported release's frozen identity.
- **Requested default:** initialize an otherwise unconfigured project's **primary** favorite as Fish Audio voice ID `6ab4c6b0f37f4243a99046478647be94`. Do this for an existing project only when it has no saved primary/explicit voice choice; never overwrite a selection on migration or project reopen. Display the ID and a neutral name until a legitimately sourced voice description is available. Seeding the ID **does not** prove account availability, gender, language, commercial rights or consent; label these as unverified until checked. Do not automatically audition, synthesize or send text to Fish.
- Every project can explicitly set **Primary**, **Secondary** and later ordered voices by reordering a single list or selecting a role inline. Exactly one primary per project when a usable favorite exists; rank changes are atomic and survive restart. The primary is the **first suggested choice**, the secondary is the **second suggested choice**, not an automatic failure fallback or a guarantee a provider accepts the ID. Other projects' choices remain isolated. Duplicate entries for one provider+voice ID should merge tags or be rejected with a helpful message; an identical ID from another provider is a different voice mapping.
- Suggested resolution priority for each spoken beat: **explicit beat override → assigned character voice → explicitly selected narrator voice → project's ordered favorite(s)**. For an unassigned first speaker suggest primary; for a different unassigned speaker suggest secondary, then later ranks, **but require visible selection/confirmation when no distinct authorized voice exists**. A narrator may deliberately reuse a character's voice; never assume every character must sound different. A provider failure or permission failure does not silently swap the speaker to another voice.
- Keep ordered favorites separate from existing logical `VoiceProfile` definitions and provider-specific mappings. Bind cast/beat references to revisioned profiles/mappings and freeze resolved voice/provider/model/consent in a render snapshot. A changed voice invalidates only its dependent speech, alignments, mouth cues, mix, captions and affected video segments; unchanged beats remain eligible for hash-checked reuse.

**Acceptance:** Save/rename/tag/reorder two Fish voice IDs, mark primary/secondary, reload both the app and local backend and see identical ordering; migrate a project with an explicit voice without modifying it; open a different project without leaking voices; reject malformed IDs/unsupported locales/duplicate ranks and missing rights without losing the draft. A mock TTS export must select the bound voice per beat; provider calls require explicit authorization.

## 2. Character voices, cast and conversation + narration — P0/P1

**Implemented persisted assignment slice:** Every saved Character Studio ZIP revision has a small project-voice selector with primary/secondary ordering from the project favorites list. A selection stores the exact voice provider/ID/tags in versioned SQLite registry `0020` keyed to a real immutable draft ID, project, character, and revision; the server verifies each owner tuple before accepting a write. An intact old browser registry is promoted only when the server has no record, and conflicts require explicit choice. Clearing one character never changes another. Old selections survive favorite removal visibly; corrupt settings and stale writes fail closed. These are **not** rights-reviewed voice profiles. **Implemented scene persistence/renderer slice:** migration `0021` holds a JSON-validated, revision-checked scene-cast registry keyed by project and *immutable source* SHA-256. GET distinguishes absent from intentionally empty. PUT rejects unknown speaker fields, duplicate shots, inconsistent character identities and stale writes. The embedded Director suggests Pip, Quill and saved character bindings or ranked favorites, saves its explicit speaker via the validated `/edit` endpoint, and commits speaker changes and Undo/Redo before claiming a save. On a new browser it rebuilds the exact scene mapping through that same validated editor API without altering other saved visual/script fields; mismatches require "Use saved scene cast" or "Keep this browser cast". Existing browser casts migrate only when no server record exists; a failed sync cannot silently start an unvoiced draft. A frozen render beat receives `{id,role,voiceId}` and Production's Check/Start allow only IDs declared by validated scenes, after ephemeral consent and same-provider validation. The selected scene's voice sample uses its own ID. Fish/local speech uses per-voice SHA-backed reuse, with a real FFmpeg synthetic Pip/Quill/narrator/Pip stem and speaker/voice provenance in the draft manifest. Commercial multi-voice release still fails closed pending independent rights. **Limitations:** only saved production/storyboard sources with a stable SHA use the SQLite cast registry; manually imported ad hoc JSON remains local. Changing Character Studio defaults never retroactively edits a frozen scene, and no live multi-browser/Cargo proof has been run.

- A **character** has a stable identity plus immutable approved revisions. Save a character's preferred `VoiceProfile`/provider mapping revision, locale, pronunciation and permitted usage as part of its revisioned character metadata; the project/production cast pins its chosen revision. A character can have an explicit *production-only* voice override without changing the reusable character catalog. Changing the default character voice must not retroactively change an already approved render.
- Make **Conversation + narration** a one-click starting template from **Create Video** alongside ordinary **Narrated explainer**. Start with two character slots and one narrator slot; preselect saved characters and ordered primary/secondary suggestions when available. Allow adding/removing characters, a narrator-only shot, visual-only scenes, dialogue-only scenes, more speakers, deliberate pauses and scene-by-scene voice changes. Template choice is **editable metadata**, not a rigid global format.
- Present one **scene strip + dialogue/narration beat list** within the embedded Director. Each beat has a stable ID, source script/claim links, text, locale, speaker kind (`character`/`narrator`), optional cast/character ID, pinned voice profile, delivery, start/sequence/overlap direction, captions and relevant character action. **Add dialogue**, **Add narration**, **Duplicate beat** and **Change speaker** are available inline without a separate wizard or page change. Preserve editing/undo, provenance and unaffected sections after storyboard revisions.
- Support patterns such as **Pip speaks → Quill answers → visuals continue while narrator explains → Pip reacts → narrator returns**, including dialogue/narration within the same scene. Speech is synthesized and aligned **by stable beat**, sequenced on an authoritative sample clock, and mixed with intentional pauses and explicitly authored overlap. Narration may continue over silent character animation or footage; do not accidentally mix two intelligible voices on top of each other merely because beats share a scene. When intentional overlap is requested, provide per-speaker gain/ducking and audibility checks. Show speaker-labeled captions without obscuring vital visuals.
- Resolve voices and rights **before** submitting paid synthesis; errors identify the specific scene/beat/character, voice/profile and safe correction. Send authorized TTS only for changed/uncached beats and use the existing Rust Jobs DAG for synthesis, alignment, character performance, render and mix. Jobs must show scene/speaker context, cancellation, bounded retries, provider failures, lost claims and nonduplicating recovery; never leak credentials or raw private provider responses. Keep the first draft's automatic progression once authorized, with **explicit confirmation for second and subsequent completed versions**.
- Honor the currently pinned Kumiki presenter capabilities: don't promise accurate lip-sync, character compositing or choreography until working/QA'd. If a saved rig cannot perform an action or render a mouth track, mark the capability and required fix rather than silently dropping that speaker. Validate lip sync, collisions, pacing, speaker captions, voice identity, pause lengths and final FFmpeg audio against edited text at normal speed.

**Illustrative authoring intent only — not an implemented API or wire schema:**

  "schemaVersion": 1,
  "videoType": "conversation-with-narration",
  "cast": [
    { "castId": "pip-role", "characterId": "pip", "voiceProfileRef": "project-voice:primary@1" },
    { "castId": "quill-role", "characterId": "quill", "voiceProfileRef": "project-voice:secondary@1" }
  ],
  "beats": [
    { "beatId": "b1", "shotId": "s1", "kind": "dialogue", "castId": "pip-role", "text": "What happens next?" },

**Acceptance:** In a real project, assign distinct saved voices to two different characters and a narrator; save/reopen and edit a middle dialogue line; export a full narrated MP4 where the first and third characters/narrator appear/speak in the correct order, audio and subtitles match, a narrator continues over scene visuals, and unchanged speech remains cached. Cover a deliberate overlap and a provider/rights failure with visible Jobs diagnostics and safe retry. Run an actual browser/FFmpeg playback review as well as mock/provider-neutral tests.

## 3. Embedded Video Director in Production — P0

**Implemented UI slice:** The existing video editor, media, sound, voice and export controls render directly within Production's Create Video step with compact local navigation. The duplicate top-level Director destination is removed. The same Director component stays mounted while moving among guided Production steps **and a Jobs & QA roundtrip, even during an unsaved scene edit**; unsafe navigation and project switches still block with a warning. On Jobs entry keyboard focus moves to its visible workspace; the hidden Production subtree is inert and relinquishes the skip-link ID. This preserves local render/voice logic but is **not** proof of the full acceptance flow: live browser/FFmpeg, cast and narration-over-dialogue, surviving other top-level sections/reloads, and responsive/accessibility QA remain open.

- **Production is the only video-making workspace.** Embed Director's current Storyboard, Find visuals, Sound, Voices/Cast, Preview and Export components directly inside **Production → Create Video**. The current separate `video-director` sidebar destination and `Production → Video Director → Production` hops should disappear from the normal workflow. Preserve existing saved storyboard/production identifiers, per-scene editing, session migration, voice consent, retry and Jobs links; consolidate shells rather than rewriting rendering engines.
- Once a script is ready, **Generate draft video** still starts the **first** private draft automatically after required readiness/voice consent. The same screen displays preflight failures, exact affected scene, Jobs progress, cancellation, retries, review stills, MP4 playback and **Generate updated version** with confirmation for completed version 2+. Editing a scene and saving it must not require navigating away/back to discover export.
- Primary layout: one persistent production stepper at the top/side, a compact scene strip, main scene editor/preview and contextual inspector tabs for **Visuals / Audio / Voices & Cast / Export**. Reveal advanced rig and mix controls only when requested. Preserve scene selection, scroll, undo/history, pending jobs and video playback while switching local tabs. Use existing Kumiki UI components and ContentGen tokens; do not add duplicate page headers, back buttons, two unrelated steppers or parallel project selectors.
- Responsive: desktop retains scene context while editing; on narrow screens use a single-column tabbed inspector with scene selector always reachable, no horizontal overflow or hidden primary action. Ensure visible keyboard focus, focus restoration after changing inspector/scene, accessible speaker names, captions and Jobs status, and concise English/Japanese labels. Use subtle motion only for intentional panel changes and honor reduced motion. A failed task keeps the editor context and typed actionable error on the same page.

**Acceptance:** From **Production → Create Video**, edit Pip's line, save, generate a first draft, inspect its Jobs, review/download the MP4, adjust Quill's voice, and confirm a second version **without ever entering another top-level page**. With a preconfigured authorized voice and script, first-draft intent requires one action and no redundant confirmation; repeated generation remains gated. Verify desktop/mobile, keyboard, English/Japanese, refresh and backend restart, empty/error/running/success states, unsaved changes and no lost edits.

## 4. Character ZIP guidance and Pip/Quill starters — P1

**Implemented starter ZIP slice:** Character Studio now shows the exact manifest fields accepted by its importer, the safe ZIP layout, live sample JSON, and downloadable teaching JSON/ZIP. Pip and Quill now have distinct, checked-in starter ZIPs with separate transparent PNG part layers rasterized from their original video-export vector puppets. A dedicated offline build script, `inspectCharacterZip` tests, pinned package SHA-256 and on-open validation prevent a missing/corrupt package from being saved. The project-scoped **Use Pip / Use Quill** buttons import and save the exact original revision in one click, while existing project revisions reopen without overwriting customized work. A silent Play/Pause motion preview uses the existing character evaluator. **Still open:** render uploaded or calibrated *user revisions* in Production (rather than the builtin versions), prove real multi-speaker MP4 playback/gesture visual quality, and verify per-character voice rights independently of artwork rights.

- Replace the current three-sentence **ZIP format and rig instructions** disclosure with structured, concise help: a file tree (`character.json` at ZIP root, referenced transparent PNG/WebP in `layers/`, optional docs), a **field-by-field explanation** of the importer-supported schema, a copyable syntax-highlighted `character.json` example, **Download example character.json**, and **Download example character ZIP**. Examples must actually pass `inspectCharacterZip` and be importable; offer checked-in offline sample files or a deterministic local download generator, not dead links. Explain which additional optional Kumiki rig/speech fields are supported versus only preserved and not validated. Link to [the current import guide](../../how-to-import-character-pack.md) for further detail.
- The example must cover `schemaVersion:1`, `characterId`, `revision`, `mode`, `design`, `channels`, `palette`, `assets` with `layers/` paths, dimensions/media types/provenance, `parts` with parent/channel/asset/pivot/z, `poses`, `basePose` and `capabilities`. Show at least one mouth variant/speech mapping when supported; indicate coordinate units, source/rights expectations, image transparency, required vs optional fields, size limits and a before/after validation-error example. Do not teach invented rig features or accept arbitrary archive paths.
- Bundle **Pip** and **Quill** as two **distinct, visible, ready-to-inspect starter characters** in Character Studio/Production cast for a new project. Seed them once with stable IDs and locally packaged, rights-cleared original art, actual validated rig ZIPs/metadata and starter expressions/poses, plus clear tags/identity. **Neither may be just a name in a test fixture, a fabricated voice permission or a link to a missing pack.** Starter voices are merely project-level suggestions until approved; the owner may change them. Existing project edits, intentional removals and newer versions must not be overwritten or re-seeded on reopen/migration.
- Offer **Use Pip and Quill** directly in the conversation template and an **Inspect/Customize** action beside each; import and download examples remain available without a project or live Fish credentials. The Characters library should preserve each character's current voice binding separately from the reusable artwork revision. Include the pack's license/attribution and export approval status without suggesting its art rights automatically grant TTS voice rights.

**Acceptance:** Fresh project shows Pip and Quill without uploading ZIP files; opening either inspects actual layers and plays only supported actions; downloaded example JSON and example ZIP pass the same production importer with the same declared assets; malformed ZIP shows the exact missing/unsafe field and a correction; a second project gets its own links without mutating the catalog; reopening does not restore a character the user removed. Browser and mobile help can be used by keyboard and screen reader in both languages.

## Delivery order and unchanged release gates

1. **P0 data & acceptance:** versioned project voice favorites + default Fish ID, scoped character voice bindings and negative SQLite/migration tests. Then speaker-aware beat/mix/caption integration with Jobs evidence and offline multiple-speaker tests.
2. **P0 unified flow:** embed existing Director inside Production; remove redundant navigation; retain readiness/consent and first-vs-later draft rules. Run UI interaction tests and a real browser walkthrough.
3. **P1 character starter UX:** validated example downloads, expanded help and real Pip/Quill starter packs with proven rights. Verify rendered character/speech behavior against the pinned Kumiki capability set.

Do not mark any new requirement complete until its specific acceptance test passes. Existing outstanding items remain: authorized browser edit-to-narrated-MP4 proof, consistently relevant rights-checked footage per scene, and a real Rust/Node restart/lease/provider-uncertainty drill. No implicit Fish API usage, voice cloning, external media download or publishing is authorized by this specification.
