# Video Test Studio — local UI design

**Intent.** Let one person test the existing ContentGen end-to-end draft-video pipeline on a Mac without copying long terminal commands. Success is an actual video, narrated audio, captions, selected frames and a truthful QA report accessible in a browser, with a clear error when a prerequisite is absent.

## Scope and boundaries

- Launch via `pnpm video:studio` from `apps/web`, then open a localhost URL. No account, deployment, database, extra frontend dependency or separate Rust daemon.
- Use the existing validated House Math **smoke** (quick feedback) and **8-minute-plus** (expensive/slow) fixtures. These are labeled illustrative and test-only; no portrait mode, arbitrary job editing, publishing or commercial-release claims in this slice.
- Pick Fish Audio `s2.1-pro-free` with an authorized reference or a user-installed loopback TTS endpoint. The test UI collects an API key in a password field or uses the existing process environment. Never persist, echo, or log credentials. No automatic voice/model installs.
- Explicit provider/voice and narration-transmission consent. Readiness runs an export build and local preflight; **only Render** sends narration to an approved external provider. Paid models stay blocked; no publishing or uploading.
- Serve HTML/CSS/browser JS and a tiny HTTP API from a Node process bound to `127.0.0.1`. This is an independent test harness, not a duplicate primitive layer inside the existing React editor. Later, the React editor can consume the same worker-oriented API contract.

## Flow

1. Choose duration fixture and voice provider, enter the voice settings and acknowledge permissions.
2. `Check readiness` builds the scene and runs `inspectProduction` with the selected settings. Show each real finding; no fake success.
3. `Render test` is enabled only for the exact configuration that passed preflight. It creates a unique job-owned directory under `~/Movies/ContentGen`, invokes `produceVideo` and reports real stages and completed capture batches; `Cancel` uses the worker's abort signal.
4. Read final QA and watch the MP4/listen to voice/master WAV, download SRT/manifest, inspect selected PNG frames. Access to all media is restricted to the latest completed job and explicit filenames.

## Security and failure handling

- Loopback-only binding; random per-server token for mutating API requests and scoped artifact URLs; no CORS; origin checks; request-byte limit and strict JSON input validation.
- No arbitrary paths, URLs, shell strings, or executable arguments from the browser. Output directory is always generated by the server. Local TTS endpoints must be loopback.
- One preflight or render at a time. Missing builds, tools, voice permission, TTS failures, cancellation and bad media produce visible, honest failure states. All media remains drafts with `commercialReady: false` unless future rights/review workflows explicitly change.
- Preserve existing release and resumable segment behavior. Failed jobs do not expose staged media as a release. Long renders may take substantial disk and processing time; display frame counts rather than invented completion percentages.

## Checks

- Node tests for the actual HTTP routes, consent gates, preflight-to-render state, token/origin protection, content allowlists/range serving, concurrent requests and cancellation.
- Pipeline tests for progress events, correct generated output and failures. Run existing headless suite and GitHub frontend checks. A real Fish→Chromium visual export requires a separate user-authorized local manual test.
