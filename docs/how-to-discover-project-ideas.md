# Project idea discovery (local-first)

Start the two existing services: `cargo run -p contentgen-server` and `pnpm --dir apps/web dev`. Open **Projects**, choose an existing project, and ensure its name and description clearly define your channel or content focus.

1. Under **Project keywords**, add topics, concrete search questions, and exclusions yourself. **Suggest with local AI** asks for no more than two phrases per serial local-model request (up to 12 calls across topic angles, aiming for 12 useful phrases). AI keyword text targets **2–5 searchable words**, with a hard cap of seven for technical terms; the separate rationale explains the fuller viewer question. For example, use `property tax reassessment` as a keyword and save `Why do property taxes rise after buying a house?` for later video-idea development. Verbose model suggestions are rejected; the next small request asks for compact replacements without spending extra requests. Each validated batch appears immediately; you can **Accept**, **Skip**, or **Stop and keep results** without waiting for later batches. An interrupted or failed generation never removes suggestions already received. Truncated JSON retries with a larger output ceiling; Qwen3.5/3.6 requests disable unnecessary thinking output when supported. Quality checks reject broad project-name echoes, boilerplate, overly long phrases and overlapping intents. Existing manually accepted keywords are not rewritten. The review panel shows request/rejection counts and partial progress; suggestions are **unverified hypotheses**, not observed keyword demand. Nothing activates itself.
2. Optionally link existing YouTube watchlists to this project in **Knowledge & sources**. Collect observations from the YouTube Intelligence screen using your configured YouTube Data API key. Linking never triggers additional collection or spends YouTube quota.
3. Optionally start local SearXNG using the existing `pnpm --dir apps/web research:up` workflow. Search results are **unverified leads** (title/URL), not fact-checked article passages.
4. Click **Discover 5 Ideas**. Only this action creates or refreshes the project's knowledge graph and starts an idea-discovery job. The worker imports eligible cached YouTube observations and searches with up to two focused accepted keywords (or description-derived search phrases if none are active). If those searches capture no evidence, it tries distinct description-based alternatives, up to **four queries total** and **20 relevant imported leads total**. Clicking starts these optional local SearXNG searches, which may forward the submitted phrases to public search providers; never put secrets in your project description. It attempts at most six bounded public-page captures with SSRF, size, and timeout checks. Search leads that cannot be captured remain unverified and **cannot** back a completed idea. Already captured passages can be reused on later clicks. The local model extracts a few quoted graph relationships at a time and proposes at most three ideas per four-source candidate-generation batch. No scheduled discovery runs in the background.
5. View the graph's topics, related sources, supported-versus-hypothesized links, and dated provider observations. Search nodes, add or remove human-approved topic aliases, and reject/reopen suggested relationships when they are incorrect. The creator's alias corrections also improve future duplicate-idea detection. Inspect the source URLs for each suggested angle. Save or dismiss individual ideas. A saved idea joins the browser's original project content list; **Save & research** opens Research with the idea and its unverified source leads prefilled. Research still requires claim verification before storyboarding.

The project catalog remains browser-local. The Rust SQLite service keeps a bounded, project-scoped mirror of titles/metadata, keyword preferences, graph provenance, discovery runs, decisions and deduplication history. A new run freezes its server-authoritative project name, description, keywords and content metadata. It saves completed search queries, graph proposals and four-source candidate batches separately. **Resume** uses the same frozen inputs and skips those completed subtasks; if a quota-limited search was interrupted after its attempt was reserved but before its results were saved, the system does not silently repeat it. Start a new explicit run to retry that uncertain search. A duplicate click reuses the active run; an active/paused run can be cancelled. One heavyweight local model request runs at a time; invalid structured model output gets bounded retry attempts rather than endless loops. Secrets and private content are not included in worker error logs. Deleting a browser project queues the corresponding server-side graph/history deletion until the local server becomes available.

An optional local fallback model may be chosen from an existing **Studio Settings → Local AI** profile by setting `CONTENTGEN_DISCOVERY_FALLBACK_PROFILE_ID` to that profile's ID before starting the Studio server. If the primary research model returns invalid structured data or encounters a retryable provider problem, a remaining attempt uses the fallback profile. The fallback is **opt-in**, local-only, and never changes the saved default profile. Storyboard jobs separately honor `CONTENTGEN_STORY_FALLBACK_PROFILE_ID`.

## Current data limitations

- **YouTube**: only manually linked watchlists' existing, unexpired public observations are imported. Their views are lifetime counts recorded at a known observation time, *not* evidence of recent view velocity or competitor success.
- **Search/news**: SearXNG produces public search leads. The worker attempts a small number of public-page captures when you click. A captured quote can support a graph relation; that does not verify every fact in the article or establish its publication date. Evidence links in the cards remain subject to human review.
- **Search troubleshooting**: A saved SearXNG port/config does not prove the Docker search service is running. If Discovery reports **Search service is unavailable**, run `pnpm --dir apps/web research:up` then `pnpm --dir apps/web research:check`, and start a **new** explicit discovery run. The run status distinguishes unreachable service from searches with zero relevant leads or zero captured passages. Neither condition fabricates research-backed ideas.
- **Google Trends**: the official Google Trends API is access-controlled. Until official access and a verified connector are configured, the UI marks Trends unavailable and the app never invents scores.
- **Five is a maximum, not a promise**: if there are too few useful sources, or all fresh angles duplicate published/saved/dismissed work, fewer ideas (or **insufficient evidence**) are shown.
- **Persistence**: graph/idea data lives in the local server's SQLite DB and must be backed up separately from browser localStorage. Deleted projects are cleaned individually from the server once it is reachable. New runs checkpoint completed search, graph and candidate subtasks. A crash in the middle of an individual inference call can require that unfinished call to be repeated; existing, interrupted pre-migration runs should be restarted as new runs rather than silently switching inputs.

Source-grounded graph relations require a captured verbatim passage to be marked supported; search leads and YouTube title matches stay hypotheses. Causal edges cannot be auto-promoted to supported claims.
